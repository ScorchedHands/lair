# Role & Objective
You are an expert AI Systems & C++/CUDA/SIMD Inference Engineer. Your task is to design, prototype, and benchmark a **Phase-Adaptive Residual Hybrid MoE Inference Pipeline** targeting **Qwen3.8-Flash-Next** on a **Dual Intel Xeon E5-2683 v4** server (32 cores total across 2 NUMA sockets, 40 MB L3 cache per socket, AVX2 instruction set, 256 GB DDR4-2400 RAM split 128 GB per socket).

# Core Architectural Concept
To simultaneously beat compute-bound prefill bottlenecks and DRAM-bandwidth-bound decode bottlenecks on Broadwell CPUs, decompose each MoE expert matrix $W_e$ into two cooperative components:
$$W_e \approx (A_{\text{shared}} \times B_e) + G_{\text{cluster}}(\text{id}_e)$$

1. **Linear Low-Rank Core ($A_{\text{shared}} \times B_e$):**
   - Captures ~75–85% of the expert's matrix variance via truncated SVD + lightweight recovery fine-tuning.
   - **Prefill Mode Execution:** Execute ONLY $(x \cdot A_{\text{shared}}) \cdot B_e$ without materializing $W_e$. This cuts prefill AVX2 FLOPs and DRAM reads by >70%.
   - **KV Cache Alignment:** For the final 16–32 tokens of any prefill prompt, run the full Linear + Residual path to prevent KV cache drift before decode begins.

2. **L3-Resident Non-Linear Residual Generator ($G_{\text{cluster}}(\text{id}_e)$):**
   - Partition each layer's 512 experts into 8 semantic clusters of 64 experts based on router co-occurrence.
   - Train a compact 2-layer non-linear hypernetwork (quantized to `Q4_0` or `Q8_0`, ~3–5 MB per cluster) conditioned on `expert_id` to output the remaining ~15–25% high-frequency residual weight matrix.
   - **Decode Mode Execution (`batch = 1`):** Load only the active cluster generators (~12–18 MB total) into each socket's 40 MB L3 cache. Synthesize the residual weights on the fly inside L3/L2 cache, add to the linear core output, and keep total generator compute strictly under **8–10 FLOPs per generated weight** to stay within Broadwell's ~1.2 TFLOPS AVX2 budget.

3. **NUMA & Memory Layout (256 GB Total DDR4):**
   - Partition Layers `0–23` to NUMA Node 0 (128 GB DDR4 / 40 MB L3) and Layers `24–47` to NUMA Node 1 (128 GB DDR4 / 40 MB L3).
   - Keep Qwen3.8-Flash-Next's 51B N-gram embedding table as a standard sparse hash lookup in DDR4 (do not compress it).

Decompose each MoE expert matrix $W_e$ into a **Linear Low-Rank Core** plus an **L3-Resident Non-Linear Residual Generator**:
$$W_e \approx (A_{\text{shared}} \times B_e) + G_{\text{cluster}}(\text{id}_e)$$

3. **51B N-Gram Table:** Memory-map as a read-only sparse lookup in unmanaged DDR4 (do not compress).

# Strict .NET 10 / C# Performance Constraints
To match C++ performance and prevent .NET Garbage Collector stalls across a 100+ GB model footprint, enforce these rules:
- **Target Framework:** `net10.0` with Native AOT readiness (`<PublishAot>true</PublishAot>`, `<AllowUnsafeBlocks>true</AllowUnsafeBlocks>`, `<OptimizationPreference>Speed</OptimizationPreference>`, `<IlcInstructionSet>avx2,fma</IlcInstructionSet>`).
